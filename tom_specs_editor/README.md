The **TomSpecs Editor** — a Tom Forge desktop app for authoring
DocSpecs / CodeSpecs / Implementation specifications.

It launches a Tom Forge shell hosting:

- a model-driven **document editor** over the bundled spec model,
- the ported **structure browser** + structural review,
- an embedded **Claude Code agent** (chat composer, prompt queue, prompt
  trail) built on the shared agent UI.

## Architecture

| Layer | Package |
| --- | --- |
| Forge shell (launcher, panels, modules) | `tom_forge_ui`, `tom_forge_core` |
| Reusable agent/chat **UI** | `tom_forge_agentic` |
| Agent provider/model API + placeholder engine (no UI) | `tom_core_agentic` |
| Spec object model + bundled `spec_model.json` | `tom_specs_model` / `tom_specs_clitool` (build-time) |

## Status

Functional. The shell registers three top-level applications — **DocSpecs**,
**CodeSpecs**, **Implementation** — behind a toolbar switcher, each with the
common **4-region layout** (document / structure / navigator + change-log /
chat). DocSpecs is the fully wired application; CodeSpecs and Implementation
render phase-aware surfaces with the real TomSpecs methodology content for their
phase.

Implemented across `lib/src/`:

- **`document/`** — model-driven document editor over the bundled
  `assets/spec_model.json` (generated by `tom_specs_clitool/bin/model_json.dart`),
  a root navigator with a model-version footer, and **DocSpecs + markdown
  import/export**.
- **`structure/`** — the ported structure browser + structural review (keyed by
  structural path; `review/structure_review.yaml`, `TOM_SPECS_REVIEW_FILE`
  override).
- **`agent/`** — an embedded spec agent suite (chat composer, prompt queue,
  prompt trail) with a spec agent engine (brain / conversational runtimes,
  memory plane, prompt composer, tools, script runner).
- **`config/`** — config editors with a config rail, preferences
  (`.tom/editor_preferences.yaml`, `TOM_SPECS_PREFS_FILE` override), and
  raw-file editing.

The working folder is the workspace: the app reads and writes it through one
`TomLocalFileSystem`, which is also its Forge shell's file system — the review
file, the preferences, `*.docspecs.yaml` documents, the files a prompt
injects, the raw config files and the agent sidecars under `.tom/`
(profiles, templates, chat variables, queue, trail, settings, bridge choice,
session id — `tom_core_agentic`'s stores, each moved by its `TOM_SPECS_*_FILE`
variable). The app starts once the review file, the preferences, the chat
variables, the profiles and the agent settings are loaded.

Version **1.0.0+1**. Covered by 31 test files carrying **272 tests**, spanning
the above areas plus undo and shell navigation.

Not published: `publish_to: 'none'`, and outside the release-1 published set —
excluded by name in
[`tom_specs_clitool/tool/release_set.yaml`](../../ai_build/tom_specs_clitool/tool/release_set.yaml),
so nothing in the released chain may depend on it.

## Build

```bash
flutter pub get
flutter analyze
flutter test
flutter build linux   # or: windows | macos
```

The suite also runs as the `editor` step of the SOM conformance driver
([`tom_som_conformance/tool/run_all_suites.sh`](../../ai_build/tom_som_conformance/tool/run_all_suites.sh)),
which is run after every model change and checks the pub cache first, so a
red editor suite is reported where model changes are checked:

```bash
../../ai_build/tom_som_conformance/tool/run_all_suites.sh editor
```
